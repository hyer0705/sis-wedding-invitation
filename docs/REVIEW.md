# 검토·보안 기준

이 문서는 **PR 하나를 어떤 기준으로 검토하고, 무엇을 리포에 들이지 않을지**를 정한다.
작업 절차 자체는 [`WORKFLOW.md`](WORKFLOW.md)를, 기능 ID ↔ 이슈 매핑은 [`FEATURE-MAP.md`](FEATURE-MAP.md)를 본다.

## 1. 이 리포의 제약 — 먼저 알아야 할 것

**GitHub의 보호 장치를 쓸 수 없다.** 프라이빗 리포 + 무료 플랜이라 다음이 전부 막혀 있다.

| 기능 | 상태 |
|---|---|
| 브랜치 보호 규칙 | 사용 불가 (`/branches/main/protection` API가 403 "Upgrade to GitHub Pro") |
| 시크릿 스캐닝 + 푸시 차단 | 사용 불가 (GitHub Advanced Security 필요) |
| 필수 상태 검사 | 사용 불가 |

즉 **`main`·`develop`에 직접 푸시하는 것도, CI가 빨간 PR을 병합하는 것도 기술적으로 막히지 않는다.** 이 문서의 규칙은 도구가 아니라 규율로 지켜진다. 대신 되돌리기 어려운 것(유출)만큼은 로컬 훅과 CI로 기계가 막는다.

```
pre-commit 훅  →  --no-verify로 우회 가능        (1차)
CI review 잡   →  우회 불가, 하지만 병합은 못 막음  (최종)
```

## 2. PR 크기 — Linear 티켓 1개 = PR 1개

| 규모 | 조치 |
|---|---|
| ~400줄 | 정상 |
| 400~800줄 | 경고. 가능하면 나눈다 |
| 800줄 초과 | PR을 나누거나 **본문에 사유를 적는다** |

400줄을 기준으로 삼는 이유는 그 이상에서 리뷰 결함 검출률이 급격히 떨어진다는 것이 코드리뷰 연구와 업계 가이드의 공통 결론이기 때문이다. 줄 수는 `package-lock.json`·`public/images/`·`dist/`를 제외하고 센다.

**같은 파일을 건드리는 기능은 한 PR로 묶는다.** 예를 들어 `CV-01`(커버 화면)과 `CV-02`(인트로 애니메이션)를 따로 PR로 내면 충돌만 난다. 티켓을 섹션 단위로 두는 이유가 이것이다.

## 3. 검토 3단계

PR을 만들기 **직전에** 순서대로 수행한다.

### ① 자동 게이트

```bash
npm run review:branch
```

시크릿·개인정보·금지 파일을 찾으면 실패한다. 아래 §4 참조.

### ② 코드 검토

`/code-review`로 변경분을 검토한다. 관점은 네 가지다.

| 관점 | 보는 것 |
|---|---|
| **정확성** | 경계값, KST 기준 날짜 계산, 빈 값·미확정 값일 때의 동작 |
| **디자인 토큰 준수** | `src/styles/tokens.css` 밖의 색상·폰트가 새로 생기지 않았는지 |
| **접근성** | 이미지 `alt`, 포커스 이동, 터치 타깃 44px, `aria-*` |
| **고객정보 취급** | `INVITE` 단일 소스를 우회한 하드코딩이 없는지 |

### ③ 셀프 체크리스트

`.github/pull_request_template.md`의 체크박스를 실제로 확인하고 채운다.

## 4. 유출 게이트 — 기계가 막는 것

`scripts/review-guard.mjs`가 검사한다. 실행 방식은 두 가지다.

| 명령 | 대상 | 호출 지점 |
|---|---|---|
| `npm run review` | 스테이징된 변경(인덱스) | `.githooks/pre-commit` |
| `npm run review:branch` | `develop...HEAD` + 커밋 메시지 | PR 직전, CI |

### 차단 항목

| 분류 | 내용 |
|---|---|
| **금지 파일** | `.env`(`.env.example` 제외) · `.DS_Store` · `*.pem` `*.key` `*.p12` `*.pfx` · `id_rsa*` · `photos-original/` · `public/images/mock/` · 래스터 원본(`.jpg` `.png` `.heic`, `public/og-image.jpg`만 예외) · 1MB 초과 파일 |
| **시크릿** | Google API 키 · Apps Script 배포 URL · Kakao 앱 키 · 개인키 블록 · 하드코딩된 secret/token/password/api_key |
| **개인정보** | 휴대폰 번호 · 주민등록번호 · 계좌번호(3~4마디) — 파일 내용과 **커밋 메시지** 모두 |

PR 크기(§2)는 경고만 하고 통과시킨다. 유출은 되돌리기 어렵지만 크기는 판단의 문제이기 때문이다.

### 예외 경로

| 경로 | 예외 범위 | 이유 |
|---|---|---|
| `drafts/` | 전체 | 시안 보관용, 읽기 전용. 13MB 원본 JPEG가 이미 히스토리에 있다 |
| `src/invite.ts` | 개인정보만 | 고객 정보의 유일한 저장소. 여기 있는 것이 정상이고 **밖으로 나가는 것이 사고**다. 시크릿은 여기서도 막는다 |
| `scripts/review-guard.mjs`<br>`scripts/review-guard.test.mjs`<br>`docs/REVIEW.md` | 시크릿·개인정보 | 룰 정의와 테스트 픽스처가 들어 있어 자기 자신을 차단하게 된다. **이 세 파일은 사람이 직접 검토한다** |

**placeholder 예외**: 모든 자리가 같은 숫자인 값(`000-000-000000` 등)은 실제 번호일 수 없으므로 통과시킨다. 이 문자열은 배포 게이트가 검사하는 placeholder라 `CLAUDE.md`·`WORKFLOW.md`·`scripts/verify-release.mjs`에 규칙으로 적혀 있고, 막으면 그 문서를 고칠 때마다 커밋이 실패한다.

**예시 번호 목록**(`EXAMPLE_NUMBERS`): 화면에 보이는 예시 번호와 테스트 픽스처는 따로 허용한다. 모두 같은 숫자로 적으면 게이트는 통과하지만 하객이 그것을 보고 「번호를 적는 칸」이라고 알아채지 못하고, CSV 가 번호를 어떻게 끊는지 검증하려면 자리 수가 실제와 같아야 한다(SIS-22 — `02`·`031` 은 국번 자리가 다르다). **이 목록에 값을 더할 때는 순차 숫자처럼 한눈에 가짜인 것만 넣는다.** 진짜처럼 보이는 번호를 여기 넣는 순간 이 게이트는 그 번호를 영원히 못 잡는다.

### 알려진 함정 — 날짜 오탐

계좌번호 정규식은 ISO 날짜(`2027-01-24`)와 형태가 같다. `INVITE.dateISO`·`.ics`·OG 태그에 실제로 등장하는 값이므로, 검사 전에 날짜를 같은 길이의 공백으로 덮어 무력화한다.

이때 **앞뒤 경계가 필수**다. 경계가 없으면 4마디 계좌번호 `123-456789-01-011` 안의 `6789-01-01`이 날짜로 잡혀 마스킹되고, 정작 계좌번호를 놓친다. `scripts/review-guard.test.mjs`가 이 회귀를 고정하고 있으니 정규식을 손볼 때 반드시 함께 돌린다.

### gitleaks를 쓰지 않은 이유

업계 표준은 gitleaks + GitHub push protection이다. 여기서 자체 룰셋을 쓴 이유는 셋이다.

1. 푸시 차단을 플랜 제약으로 못 쓴다 (§1)
2. brew 바이너리 의존을 CI에 넣는 비용이 이 규모에 과하다
3. **정작 막아야 할 것이 범용 시크릿이 아니라 한국식 계좌·휴대폰 번호**다. 룰을 직접 쓰는 편이 정확하다

프로젝트가 커지거나 팀이 늘면 gitleaks로 교체하는 것이 맞다.

## 5. 보안 체크리스트 — 사람이 봐야 하는 것

기계가 못 잡는 것들이다. PR 검토 시 해당되면 확인한다.

- [ ] **Kakao JS 키 도메인 화이트리스트** — JS 키는 번들에 그대로 노출된다. 숨길 수 없으므로 카카오 개발자 콘솔의 플랫폼 도메인 등록이 유일한 방어다. 배포 도메인과 Vercel 프리뷰 도메인을 등록했는가
- [ ] **Vercel 환경변수** — `.env`는 커밋하지 않는다. 새 환경변수를 추가했다면 Vercel에도 등록했는가
- [ ] **`.env`는 비밀이 아니다** — Vite의 `VITE_` 변수는 전부 번들에 인라인된다. **관리자 비밀번호처럼 진짜 비밀은 절대 넣지 않는다** (검증은 Apps Script 쪽에서)
- [ ] **외부 링크** — `target="_blank"`에 `rel="noopener"`를 붙였는가
- [ ] **새 npm 의존성** — 주 다운로드 수와 최종 릴리스 날짜를 확인했는가. `CLAUDE.md`가 정한 스택 밖의 라이브러리는 추가하지 않는다
- [ ] **개인정보 최소 수집** — RSVP에서 꼭 필요하지 않은 항목을 받고 있지 않은가. 명세서에서 미채택된 항목은 수집하지 않는다

## 6. 위협 모델 — 무엇을 걱정하고 무엇을 걱정하지 않는가

서버·DB·인증이 없는 정적 사이트다. 그래서 **인젝션·권한 상승·세션 탈취·CSRF는 해당이 없다.** 실제 리스크는 셋뿐이며 위의 모든 검사는 여기에만 집중한다.

| 리스크 | 대응 |
|---|---|
| **개인정보 유출** — 계좌번호·연락처·실명이 커밋 메시지·주석·문서·`src/invite.ts` 밖으로 새는 것 | §4 자동 차단 |
| **시크릿 유출** — `.env`, Apps Script URL, API 키 커밋 | §4 자동 차단 |
| **의도치 않은 공개** — 청첩장 URL의 검색엔진 색인 | `CM-07` — SIS-18에서 고객 확인 후 `noindex` 결정 |

리포가 프라이빗이라 코드 자체의 노출 위험은 낮다. 그래서 이미 히스토리에 들어간 13MB 원본 사진도 그대로 두기로 했다 — 히스토리 재작성 비용이 위험보다 크다.

## 7. 훅 설치

```bash
npm install
```

`package.json`의 `prepare`가 `git config core.hooksPath .githooks`를 실행한다. husky 같은 의존성은 쓰지 않는다.

설치 확인:

```bash
git config core.hooksPath
```

`.githooks`가 나오면 정상이다.
