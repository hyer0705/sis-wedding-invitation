# 실기기 수동 QA

자동화로 덮을 수 없는 것만 모은 목록이다. [`WORKFLOW.md` §7 테스트 계층](WORKFLOW.md#7-테스트-계층)의 네 번째 층에 해당한다.

**언제 수행하나**: `main` 배포 직후, 그리고 커버·지도·공유·계좌·캘린더 중 하나라도 손댄 뒤. 프리뷰 URL로도 대부분 확인할 수 있지만 **카톡 공유 카드(OG)만은 배포 주소로 해야 한다** — 스크래퍼가 프리뷰 주소를 캐싱하면 그 카드가 하객에게 나간다.

## 왜 자동화하지 못하나

| 항목 | 이유 |
| ---- | ---- |
| 카카오톡 인앱 브라우저 | WebView라 Playwright가 붙지 못한다. 자동재생·다운로드 정책이 일반 브라우저와 다르다 |
| 지도 앱 3종 연결 | 앱 스킴은 설치된 앱이 있어야 열린다. CI에는 앱이 없다 |
| 카톡 공유 카드 | 카카오 스크래퍼가 외부에서 배포 주소를 읽어야 확인된다 |
| iOS Safari 실동작 | macOS(arm64)에서 Playwright webkit 바이너리가 Bus error로 죽는다. CI의 `ios-safari`는 엔진 검증까지다 |
| 클립보드(webkit) | `clipboard-read` 권한은 chromium에만 줄 수 있다 |
| 지도가 실제로 뜬 상태의 접근성 | CI에는 카카오 키가 없어 지도가 정적 안내로 degrade된다. 그 상태의 axe 위반은 CI가 영영 못 잡는다 |

## 준비

- 기기 2대: **iOS(Safari) + Android(Chrome)**, 각각 최신 2개 버전 안 (`CM-09`)
- 두 기기 모두에 **카카오톡** 설치. 자기 자신에게 보낸 링크로 인앱 브라우저를 연다
- 지도 앱 3종(네이버지도·카카오맵·티맵)을 **한쪽 기기에 모두 설치**한다. 웹 폴백은 나머지 기기를 **3종 모두 미설치**로 두고 확인한다 — 한 기기에서 둘을 겸하면 어느 쪽이든 확인하지 못하는 항목이 남는다
- 배포 도메인이 **Kakao Developers 콘솔의 플랫폼(Web)에 등록**돼 있는지 먼저 확인한다. 미등록이면 지도가 조용히 정적 안내로 빠지고 콘솔에 에러도 남지 않는다

## 1. 카카오톡 인앱 브라우저 (`CM-02`) — 가장 중요

하객 대부분이 링크를 여기서 연다. **한 항목이라도 실패하면 그것이 사실상 전원에게 실패한 것**이다.

- [ ] 링크를 눌러 청첩장이 열리고, 부트 화면 → 로딩 화면 → 커버로 **글씨가 튀지 않고** 이어진다
- [ ] 커버부터 푸터까지 세로 스크롤이 끊기지 않는다
- [ ] **지도 위에 손가락을 올린 채 세로로 스와이프해도 페이지가 스크롤된다** — 여기서 멈추면 `Location.tsx`의 투명 덮개가 깨진 것이다
- [ ] 지도가 실제로 뜬다 (정적 안내로 빠졌다면 도메인 등록 문제)
- [ ] 주소 복사 → 토스트가 뜨고, 메모장에 붙여넣어 값이 맞는지 확인
- [ ] 계좌번호 복사 → 토스트가 뜨고, **붙여넣은 값이 화면에 보이는 값과 하이픈까지 같다** (`AC-02`)
- [ ] 카카오톡으로 공유 → 공유 시트가 뜨고 카드가 정상으로 보인다
- [ ] 「캘린더에 저장」 → **`.ics` 다운로드가 막히지 않는다** (`DT-03`). 막히면 구글 캘린더 링크 병행을 고객과 상의한다
- [ ] RSVP 제출 → 완료 카드가 뜬다
- [ ] 배경음악: 우상단 토글을 눌러 **실제로 소리가 난다** (`CV-03`) — 자세한 항목은 §11

## 2. iOS Safari / Android Chrome (`CM-09`)

인앱이 아닌 기본 브라우저에서도 같은 흐름을 한 번씩 훑는다.

- [ ] 스크롤·갤러리 스와이프가 자연스럽다. 갤러리에서 **양옆 사진이 걸쳐 보인다**
- [ ] 갤러리 화살표로도 넘어가고, 첫 장·끝 장에서 갈 수 없는 쪽이 잠긴다
- [ ] 아코디언(마음 전하실 곳)이 열리고 닫힌다
- [ ] 주소·계좌·링크 복사 3종이 실제 클립보드에 들어간다 — **iOS Safari는 자동 테스트가 못 보는 경로다**
- [ ] 가로로 눕혀도 레이아웃이 깨지지 않는다
- [ ] iOS에서 주소창이 접혔다 펴질 때 커버가 잘리거나 튀지 않는다

## 3. 태블릿·PC (`CM-01`)

430px 컬럼이 가운데 서는지만 본다. 자동 테스트(`e2e/smoke.spec.ts` 「태블릿·PC」)가 폭과 정렬을 이미 고정하고 있으므로 여기서는 눈으로만 확인한다.

- [ ] PC 카카오톡에서 링크를 열었을 때 컬럼이 가운데 서고 배경이 어색하지 않다
- [ ] **로딩 중에도 컬럼 폭이 유지된다** — 화면을 가득 채웠다 접히면 회귀다

## 4. 지도 앱 연결 (`MP-03`)

- [ ] 네이버지도 — 앱이 열리고 **좌표가 예식장을 가리킨다**
- [ ] 카카오맵 — 위와 같음
- [ ] 티맵 — 위와 같음
- [ ] 위 세 줄은 **3종을 모두 설치한 기기**에서 본다
- [ ] **3종을 설치하지 않은 나머지 기기**에서 눌렀을 때 셋 다 웹 지도로 열린다 (스토어로 튕기지 않는다)

목적지 이름만 맞고 좌표가 엉뚱한 경우가 실제로 잦다. 지도 화면에서 **건물을 확인**한다.

## 5. 카톡 공유 카드 (`SH-03`)

명세서에서 유일한 「필수」다. 깨진 채로 한 번 배포되면 스크래퍼가 그 상태를 캐싱한다.

- [ ] 배포 주소를 카카오톡 대화창에 붙여넣어 **썸네일·제목·설명**이 모두 나온다
- [ ] 썸네일이 잘리거나 빈칸이 아니다 (R2의 `og-image.jpg`)
- [ ] 값을 고친 뒤라면 [카카오 디버거](https://developers.kakao.com/tool/debugger/sharing)로 **캐시를 갱신**하고 다시 본다
- [ ] 「링크 복사」로 복사된 주소가 **프리뷰 주소가 아니라 배포 주소**다

## 6. RSVP 도착 확인

- [ ] 참석 1건을 실제로 제출하고 **Supabase `rsvp` 테이블에 행이 들어오는지** 확인한다
- [ ] 미참석으로도 1건 제출해 본다 — **연락처가 필수**다(SIS-37). 비운 채로는 동의·제출 버튼이 나오지 않고, 적은 번호는 `phone` 에 그대로 들어간다
- [ ] 미참석 회신의 `count` 는 1, `meal` 은 `식사안함` 이다 — 화면에서 묻지 않고 채우는 값이다
- [ ] 참석 회신의 `meal` 이 화면에서 고른 문구와 **글자까지 같다** — `식사함`·`식사안함`·`미정` (SIS-35). 옛 값 `식사` 가 보이면 alter 가 적용되지 않은 것이다
- [ ] 같은 기기에서 다시 제출하려 하면 중복 방지가 동작한다 (localStorage)
- [ ] 확인 후 테스트로 넣은 행을 지운다

참석 명단은 anon 으로 읽히지 않으므로(RLS) **화면에서는 도착을 확인할 수 없다.** 반드시 대시보드의 테이블을 본다.

### keep-alive 워크플로 (SIS-33)

무료 티어는 DB 활동이 7일 없으면 일시정지된다. 예약 실행에 기대기 전에 한 번은 손으로 돌려 본다.

- [ ] Actions 탭 → **keep-alive** → Run workflow → 초록으로 끝난다

**이 워크플로는 `main` 에 올라간 뒤에야 Actions 탭에 나타난다.** 예약 실행도 「Run workflow」 버튼도 기본 브랜치에 파일이 있어야 생기는 GitHub 제약이라, `develop` 에만 있는 동안에는 확인할 방법이 없다 — 릴리스 직후에 본다.

리포 시크릿 `SUPABASE_URL`·`SUPABASE_PUBLISHABLE_KEY` 가 필요하다(`VITE_` 접두사 없음). 이름이 틀리면 워크플로가 「시크릿이 없습니다」로 즉시 실패하므로 그 메시지로 구분할 수 있다.

## 7. D-Day (`CV-04`)

- [ ] 남은 일·시·분·초가 **KST 기준**으로 맞고 초가 1초마다 갱신된다
- [ ] 기기 시간대를 KST가 아닌 곳으로 바꿔도 값이 흔들리지 않는다

## 8. 접근성 — 지도가 뜬 상태

CI가 볼 수 없는 구간이라 **카카오 키가 들어 있는 로컬**에서 한 번은 봐야 한다.

- [ ] 지도가 뜬 상태로 axe를 돌려 critical/serious를 확인한다. 카카오 마커가 넣는 `<area>`의 빈 alt(`area-alt`, critical)가 알려진 예다
- [ ] iOS VoiceOver로 커버 → 초대글 → 갤러리까지 훑어 읽히는 순서가 화면 순서와 같다

## 9. 방명록 (`GB-01`·`GB-02`·`GB-03`, SIS-21)

자동 테스트가 못 보는 것은 **전체보기 화면의 스크롤과 뒤로가기**다. 둘 다 실기기에서만 드러난다.

- [ ] 메인 방명록 섹션에 **최신 5개**가 보이고, 6개째가 있을 때만 「전체보기」가 뜬다
- [ ] 축하 메시지를 남기면 목록에 바로 올라온다 — **Supabase 대시보드의 `guestbook` 테이블**에도 행이 들어왔는지 함께 본다
- [ ] 남길 때 정한 비밀번호로 지워진다. **다른 비밀번호로는 지워지지 않고** 팝업이 닫히지 않는다
- [ ] 「전체보기」를 누르면 주소가 `/guestbook` 으로 바뀌고, **X 로 닫으면 보던 자리로 돌아온다** (커버 맨 위로 튀면 안 된다)
- [ ] **안드로이드 뒤로가기 버튼**으로도 닫힌다 — 청첩장 밖으로 나가 버리면 안 된다
- [ ] ⚠ **iOS Safari** 에서 전체보기를 열고 목록 끝까지 스크롤한다. **뒤쪽 청첩장이 함께 밀리지 않아야 한다** — `body` 에 `overflow:hidden` 을 걸어 잠그는 방식이라 iOS 에서 새는 것으로 알려져 있다. 밀린다면 잠금 방식을 바꿔야 한다
- [ ] 배포 주소에 `/guestbook` 을 **직접 입력**해 들어가도 404 가 아니고, 로딩 화면이 목록을 덮지 않는다
- [ ] 「더보기」로 이어 읽은 뒤 한 건을 지우면 **읽던 만큼이 그대로 남는다** (10개로 되감기면 안 된다)
- [ ] 카카오톡 인앱 브라우저에서 작성과 삭제가 동작한다
- [ ] 방금 남긴 글이 **관리자 방명록 탭**(§10)에도 같은 내용으로 보인다

## 10. 관리자 페이지 (`AD-01`·`RS-04`·`GB-04`, SIS-22·SIS-38·SIS-40)

화면은 SIS-38 이 채웠고 **방명록 탭은 SIS-40 이 채웠다.**

### 대시보드 설정 — 이것부터 본다

- [ ] Authentication → Sign In / Providers → Email → **「Allow new users to sign up」이 꺼져 있다.** 켜져 있으면 번들의 publishable 키로 누구나 계정을 만들 수 있다
- [ ] Authentication → Users 에 관리자 계정이 있고, 그 **UID 가 `admin_users` 에 들어 있다.** 등록하지 않으면 로그인은 되지만 목록이 0건으로 보인다
- [ ] `npm run smoke:rls` 가 ①~④ 모두 통과한다 — 하객(anon) 시선에서 명단·관리자 uuid·`is_admin()` 이 전부 막혀 있는지 본다

> 권한이나 정책을 고친 **직후**에는 ④ 가 실패할 수 있다. PostgREST 가 스키마 캐시를 갱신하는 데 몇 초 걸리기 때문이며, 잠시 뒤 다시 돌리면 통과한다. 두 번째 결과가 실제 상태다 (SIS-39).

### 접근

- [ ] 배포 주소에 `/admin` 을 **직접 입력**해 들어가도 404 가 아니다 (Vercel SPA fallback — `vercel.json`)
- [ ] `/admin` 에서 페이지 소스의 `<meta name="robots">` 가 `noindex` 다. 청첩장과 같은 HTML 을 쓰므로 자동으로 붙는다 (`CM-07`)
- [ ] 오타 주소(`/adminn` 등)로 들어가면 청첩장이 뜬다

### 로그인

- [ ] 관리자 계정으로 로그인하면 목록이 뜬다
- [ ] 새로고침해도 로그인이 풀리지 않는다 — **로그인 화면이 잠깐 보였다가 목록으로 바뀌지 않는다**(확인이 끝날 때까지 부트 화면이 떠 있어야 한다)
- [ ] **`admin_users` 에 없는 계정**으로 로그인하면 「관리자 권한이 없습니다」가 뜬다 — 빈 목록이 아니라 권한 문제로 보여야 한다
- [ ] 비밀번호를 틀리면 한국어 안내가 뜬다 (영문 원문이 그대로 나오면 안 된다)
- [ ] 로그아웃하면 목록이 사라진다
- [ ] 탭을 두 개 열어 두고 한쪽에서 로그아웃하면 **다른 쪽도 로그인 화면으로 돌아간다**

### 조회·삭제·CSV

- [ ] 목록이 **최신순**이고, 집계(참석·미참석·식수)가 대시보드의 테이블과 맞는다
- [ ] 회신 한 건을 지우면 목록에서 사라지고, **새로고침해도 되살아나지 않는다**
- [ ] 삭제 확인 팝업에 **지우려는 사람의 이름**이 맞게 뜬다 — 목록에서 누른 자리와 어긋나면 안 된다
- [ ] CSV 를 내려받아 **엑셀에서 연다** — 한글이 깨지지 않고(BOM), **연락처 앞자리 0 이 살아 있다**(`010-…`)
- [ ] 미참석 회신의 인원·식사 칸이 비어 있다
- [ ] **카카오톡 인앱 브라우저**에서 CSV 다운로드가 막히지 않는지 본다 — `.ics` 와 같은 경로다. 막히면 기본 브라우저로 열어 받는다

### 필터·탭 (SIS-38)

- [ ] 참석 여부·양가 세그먼트와 검색이 목록을 좁힌다
- [ ] **필터를 걸어도 집계와 「CSV 내려받기 (N건)」의 숫자는 전체 그대로다** — 거른 파일을 전체로 착각하면 식수를 잘못 주문한다
- [ ] 화면에 보이는 하이픈 형태(`010-1234`)로 검색해도 연락처가 걸린다
- [ ] 맞는 회신이 없으면 적은 검색어가 그대로 안내에 뜬다
- [ ] 375px 폭에서 집계 카드의 양가 두 칸과 세그먼트 세 칸이 한 줄에 들어간다
- [ ] 두 탭 모두 카드 사이가 붙지 않고 벌어져 있다 (SIS-40 에서 탭 안쪽 간격을 잡았다)

### 방명록 탭 (`GB-04`, SIS-40)

- [ ] 목록이 **최신순**이고 건수가 `guestbook` 테이블과 맞는다
- [ ] **비밀번호를 묻지 않고** 바로 삭제 확인 팝업이 뜬다 — 하객 삭제(§9)와 갈리는 지점이다
- [ ] 팝업에 **지우려는 글의 이름과 내용**이 맞게 뜬다. 긴 글은 뒤가 「…」로 잘린다
- [ ] 한 건을 지우면 목록에서 사라지고 **새로고침해도 되살아나지 않는다.** 하객 화면(§9)에서도 사라진다
- [ ] 삭제 확정 버튼만 빨간색이고 「취소」와 색이 다르다
- [ ] 검색이 **이름과 내용 양쪽**에서 걸린다
- [ ] 글이 많아도 「더보기」가 없다 — 한 번에 다 보인다
- [ ] 긴 글과 줄바꿈이 카드 밖으로 삐져나오지 않는다 (300자 한 건으로 본다)

> ⚠ 내려받은 CSV 에는 하객의 이름과 연락처가 들어 있다. 확인이 끝나면 지우고, 메신저·메일로 옮기지 않는다.

## 11. 배경음악 (`CV-03`, SIS-27)

**자동화가 끝까지 갈 수 없는 항목이다.** 컴포넌트 테스트는 `play()` 를 불렀는지까지만 보고, E2E 는 CI 에 음원이 없어 재생을 시키지 않는다. **소리가 실제로 나는지는 여기서만 확인된다.**

### 카카오톡 인앱 브라우저 — 이것부터 본다

- [ ] 토글을 눌러 **소리가 난다.** 인앱이 오디오를 막으면 여기서 드러난다
- [ ] 막혔다면 **토글이 켜진 채로 남지 않는다** — 아이콘이 음소거로 되돌아와야 한다. 켜진 채 조용하면 하객은 자기 기기 문제로 여긴다
- [ ] 90초가 끝나면 **끊기지 않고 처음으로 돌아간다**

### 두 기기 공통

- [ ] 처음 열었을 때 **소리가 나지 않는다.** 자동재생은 하지 않는다
- [ ] 토글 아이콘이 음소거(사선)로 시작하고, 누르면 음파 모양으로 바뀐다 — 색이 아니라 모양으로 갈린다
- [ ] 커버에서 푸터까지 **어디로 스크롤해도 토글이 우상단에 남는다**
- [ ] 켠 뒤 다시 누르면 **즉시 멎는다**
- [ ] 페이지를 새로 열면 **다시 음소거로 시작한다** (상태를 저장하지 않는다)
- [ ] 방명록 전체보기를 열면 토글이 그 화면에 가린다 — 닫으면 돌아온다
- [ ] 토글이 커버 글씨·지도·카드 내용을 가리지 않는다

### iOS 만

- [ ] **무음 스위치를 켠 상태**에서는 소리가 나지 않는다. 코드로 우회할 수 없는 OS 동작이라 **정상이다** — 고객이 「안 들린다」고 할 때 가장 먼저 확인할 것
- [ ] 무음 스위치를 풀면 같은 토글로 소리가 난다

### 두 기기 공통 — 데이터

- [ ] 3G 로 낮춰도 **첫 화면이 음원을 기다리지 않는다** (`preload="none"` — 토글을 눌러야 받기 시작한다)
